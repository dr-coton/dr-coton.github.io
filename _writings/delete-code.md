오늘은 새 기능을 하나도 만들지 않았다. 대신 삼백 줄 가까운 코드를 지웠다. 그런데 이상하게도 이번 주에 가장 보람 있는 하루였다.

## 쓰이지 않는 코드가 하는 일

사용하지 않는 코드는 조용히 있는 것처럼 보이지만 실제로는 비용을 낸다. 읽는 사람은 이게 왜 있는지 고민해야 하고, 고치는 사람은 혹시 어딘가에서 쓰일까 봐 조심해야 한다. 테스트는 그 코드까지 유지해야 한다.

오래된 코드를 지우기 전에 확인한 것은 세 가지였다.

| 확인할 것 | 방법 |
| --- | --- |
| 정말 호출되는 곳이 없는가 | `grep`으로 검색하고, 동적 호출도 살핀다 |
| 언제부터 쓰이지 않았는가 | `git log -S`로 마지막 사용 시점을 찾는다 |
| 지워도 되돌릴 수 있는가 | 작은 커밋으로 나누어 언제든 `revert`할 수 있게 한다 |

## 지우는 일도 기록이 된다

이런 diff를 보는 순간이 가장 개운하다.

```diff
- function legacyExport(rows) {
-   // 2019년 이전 고객을 위한 옛 형식
-   return rows.map(formatOldStyle).join('\n');
- }
-
  function exportRows(rows) {
    return rows.map(formatRow).join('\n');
  }
```

지운 자리에는 아무것도 남지 않는다. 그게 좋다. 어디서든 필요해지면 git이 기억하고 있으니, 나는 안심하고 비울 수 있다.

> 가장 좋은 코드는 없는 코드다. 그다음으로 좋은 코드는 지울 수 있는 코드다.

새로 만드는 일에는 언제나 박수가 쏟아지지만, 덜어내는 일은 조용하다. 그 조용함이 나는 좋다.
